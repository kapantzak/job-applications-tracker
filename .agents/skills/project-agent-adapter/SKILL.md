# Agent adapter and prompts

## Purpose

The app never calls a model; it spawns the user's own CLI (Claude Code, Codex, or a custom command) and parses schema-validated JSON back. This skill keeps that boundary safe (no shell, no trust in output) and keeps the prompt contract and the parsing rules aligned.

## Scope

Use this skill when:

- editing `src/server/agents/cli-adapter.ts`, `presets.ts`, `extract-json.ts`, `index.ts`;
- editing `prompts/discover_jobs.md`, `prompts/sync_mail.md`, `prompts/analyse_cv.md`, or `src/server/tasks/schemas.ts`;
- editing `src/server/services/discovery.ts`, `src/server/services/mail-sync.ts`, `src/server/mail/agent-source.ts`, `src/server/cv/*`;
- claiming that a preset works on a developer machine.

Do not use this skill for:

- the run queue or SSE (see `src/server/runs/`), unless the change alters what the adapter receives;
- UI changes that only display run output.

## Mandatory Knowledge

- Child processes are spawned with `spawn(argv0, args, { shell: false })` and inherit `process.env` unchanged. Never build a command string. Evidence: `src/server/agents/cli-adapter.ts`, design spec section 8.
- On win32 `resolveCommand` (`src/server/agents/resolve-command.ts`) searches `PATH` x `PATHEXT` and turns an npm `.cmd`/`.bat` shim into `node <entry.js>` (from its `%dp0%` / `%~dp0` reference, quoted form first so spaces survive); a `.js`/`.mjs`/`.cjs` winner also runs under node; anything unresolvable is spawned unchanged so ENOENT still reports `Command not found: <argv0>`. POSIX is a passthrough. The win32 path is tested with simulated shims and injected `ResolveDeps` only, never on a real Windows machine. Evidence: `test/server/agents/resolve-command.test.ts`, SOW-0002.
- Placeholders: `{schema}` is replaced only as a whole argv element (inline JSON); `{schema_file}`, `{prompt_file}`, `{output_file}`, `{permission_mode}`, `{allowed_tools}`, `{sandbox}` may be substrings. Files are written under the run directory `runs/<run-id>/`. Evidence: `src/server/agents/cli-adapter.ts`, `test/server/agents/cli-adapter.test.ts`.
- `run()` and `check()` never reject; every failure resolves `ok: false` with a specific `error` (`Timed out after <ms> ms`, `Aborted`, `Exited with code <n>`, `Command not found: <argv0>`, `Failed to start: …`). Evidence: SOW-0001 Task 9 review.
- `extractLastJsonObject` takes the LAST balanced top-level object and never falls back to an earlier one; an echoed schema in prose must not become the result. Evidence: SOW-0001 Task 9 ruling.
- Every prompt template states the read-only rules (never apply, never send/draft/label mail) and ends with "Respond with a single JSON object matching the required schema and nothing else." `sync_mail.md` carries the `mail_access: false` instruction (design Decision 7). Templates have a `version:` front matter that is recorded on each run; bump it on any wording change.
- `check()` runs the version probe, then (only if it succeeded) the preset's `authArgv` (`claude auth status`, `codex login status`; custom has none) with the same 3 s timeout and resolver. Exit 0 = `authenticated: true`; non-zero = `false` plus `authMessage` (first non-empty output line, max 200 chars; never the full output, it may hold account details); spawn failure or timeout = `authenticated` undefined with `Sign-in check failed: <reason>`. Evidence: `test/server/agents/cli-adapter.test.ts`, SOW-0003.
- Preset flag spellings were verified against `claude --help` (2.1.x) and `codex exec --help` (0.163) on 2026-11-05. Re-verify on the build machine whenever a preset changes; CLIs drift.
- The Claude preset passes `--setting-sources user --disallowedTools Agent,Task`. Probed on 2.1.319 (SOW-0008): `--bare` skips keychain reads and the agent is "Not logged in"; `--setting-sources ""` drops every MCP server including the claude.ai Gmail connector that sync needs; `user` keeps credentials, plugins and connectors while skipping project `CLAUDE.md`/skills/`.mcp.json` implied by the run cwd. It also loads the user's personal `~/.claude/CLAUDE.md`, auto-memory and hooks, so both kinds pass `--settings` with `claudeMdExcludes: ["**/CLAUDE.md"]`, `disableAllHooks: true`, `autoMemoryEnabled: false` (SOW-0018). A wrong settings key is ignored silently: check with a canary prompt that asks whether personal memory and hook text are present. `--safe-mode` drops the same things but also the Gmail connector. `claudeMdExcludes: ["**/CLAUDE.md"]` is verified only for `~/.claude/CLAUDE.md`; whether it also drops `CLAUDE.local.md` or `~/.claude/rules/*.md` is unverified (neither existed on the test machine; SOW-0021). Codex flags (`--disable multi_agent`, `-c web_search="live"`) are verified on codex-cli 0.163.0 only, and README says Codex is tested on 0.163.0 or newer. Codex always reads `~/.codex/AGENTS.md` (`project_doc_max_bytes=0` covers project files only); a separate `CODEX_HOME` would hide it but Codex refreshes `auth.json` by temp file and rename, which would leave the user's own Codex home on an old token, so Codex is left as is (user decision, SOW-0018). Denying `Agent`/`Task` is the only hard stop on subagent fan-out; the first real run spent 10 minutes in 14 subagents verifying postings and never answered.
- Claude discovery flags (SOW-0016, claude 2.1.319): `--tools <built-ins from allowed_tools_discover>`, or `--tools ""` when none is allowed, which turns every built-in tool off (probed 2026-11-07; leaving the flag out would load them all, SOW-0021) (`--allowedTools` alone only skips prompts; `--tools` removes the other tool definitions), `--strict-mcp-config` unless an allowed discovery tool is `mcp__…`, `--max-budget-usd <setting>` when set. Measured 2026-11-07: with `--setting-sources user` a trivial `-p` run loaded 275,136 context tokens (≈$1.10 at sonnet list price) before doing anything; `--strict-mcp-config` cut it to 12,857. The size depends on the user's MCP connectors. The app's own sync argv (no `--tools`, Gmail tools in `--allowedTools`) on the same machine started at 47,042 tokens with MCP tools deferred, and at 26,747 with the SOW-0018 settings; which flag makes the 275k-versus-47k difference is not established, so measure with the exact app argv. Never add `--strict-mcp-config` to sync: it drops the claude.ai Gmail connector. Reaching `--max-budget-usd` ends the run with a `result` event `subtype: error_max_budget_usd`, exit 1, no structured output.
- Codex flags (SOW-0016, codex-cli 0.163.0): `--disable multi_agent` for both kinds (sub-agents are on by default); discovery adds `-c web_search="live"` (default `cached` has no live web access). Probe 2026-11-07: after its last search a `codex exec` stalled for an hour with no final message (`failed to refresh available models: request timed out` on stderr); only the run timeout ends that.
- Search operators: Codex live search honoured `site:` (all results on the named host); Claude Code's WebSearch did not (about half the results on the host, the rest aggregators; an `OR` of two hosts returned none from the first). Never rely on `site:` for correctness; dedupe and verification are app-side.
- `prompts/discover_jobs.md` is v4 (v3 from SOW-0016; v4 from SOW-0017 adds the Ashby rule below): `{{scope}}` (Default: all sources, ATS first; Max: one source family per worker), steps (short title-variant searches, search before open, Greenhouse/Lever public job lists instead of single postings, never Ashby's multi-MB list, open each Ashby posting once before returning it and drop any that fails to load, never aggregator pages to confirm), per-job `checks` verdicts, and the Budget section: about 10 minutes, at most 30 jobs, stop at about 10 strong matches, fewer is fine and never pad, one page per job, no subagents, the app verifies links. Ashby (SOW-0017, measured 2026-11-07): search results keep closed postings, a closed posting answers 404 (WebFetch reports "HTTP 404 Not Found"), a live one returns its title, and the board page is client-rendered so WebFetch sees 0 postings on it; with v3 ("use search results for Ashby postings") 5 of 48 Ashby links from the Max Ashby worker and 5 of 21 from Default runs were dead. With v4, over the same 8 runs: 0 of 49 and 0 of 20; Default cost rose about a third with about a third more live jobs. The v2 measurements below still motivate the budget. Keep that section when editing the prompt. Measured on 2026-11-06 (SOW-0008): no budget at all → 15 min with 14 subagents and 12 verified jobs; "do not open any posting" → under 2 min but 7 of 18 links dead and the rest aggregators. The default `run_timeout_ms` is 20 min for this reason. Evidence: `.superpowers` ledger and Task 9 report.
- Model and effort (SOW-0011): presets append `--model`/`--effort` (claude) or `-m`/`-c model_reasoning_effort="<e>"` (codex) only when the per-agent, per-kind setting is non-empty; `''` passes nothing and the CLI's own default applies. `selectionFor()` in `presets.ts` re-validates stored values with `MODEL_PATTERN`/`EFFORT_PATTERN` (no leading `-`, no quotes) because they reach argv. Probed 2026-11-07 on claude 2.1.319 and codex 0.163.0: `claude -p --model sonnet --effort low` ran and its init event reported `claude-sonnet-5-5`; codex plain mode printed `reasoning effort: low` for the `-c` override (the banner is absent under `--json`). Evidence: SOW-0011 Validation.
- `AgentResult.usage` (SOW-0016) is read on success and failure from `usageFrom`: Claude's last `result` event (`total_cost_usd`; tokens summed over `modelUsage`, input including cache reads and writes; `usage` is main-loop only and is a fallback) or Codex's last `turn.completed.usage`, which is the thread's running total (openai/codex `codex-rs/exec/src/event_processor_with_jsonl_output.rs`, `usage_from_last_total`), so take the last event and never sum. Codex reports no cost; custom commands report nothing. Claude's `webSearchRequests` stayed 0 although searches ran, so it is not recorded.
- Max discovery (SOW-0016) is app-side fan-out: `services/discovery.ts` runs five adapter calls with their own cwd `runs/<id>/worker-<n>/` (Codex writes `-o output.json` per cwd), the shared signal and a `[worker <n>] ` log prefix. Each worker is a normal preset run, so all preset limits apply per worker.
- `AgentResult.reportedModel` comes from the Claude stream-json `system/init` event (`extractClaudeInitModel`), on success and failure. Codex `--json` events carry neither model nor effort; no agent reports the effort. Do not parse CLI config files to guess defaults (user decision, SOW-0011).
- `listModels()` never rejects: a static `modelCatalog` (Claude aliases from `claude --help`) or `modelsArgv` (`codex debug models`, 5 s probe, parsed by `parseCodexModelCatalog`, hidden models skipped). `debug models` is a debug command with no stability promise; any failure returns `source: 'unavailable'`. Fake-agent: argv `debug models` prints `FAKE_AGENT_MODELS` (or fails with `fail`); mode `claude` puts `FAKE_AGENT_MODEL` in the init event and usage in the result event, `claude-fail` emits only init and exits 2, `claude-budget` emits an `error_max_budget_usd` result with usage and exits 1; mode `codex` prints a `turn.completed` with usage.
- Handlers work on the run's profile (SOW-0014): discovery loads `ctx.run.profile_id` and passes only that profile's known URLs and dedupe keys; mail sync sends only that profile's open applications and reviewed message ids. The profile name is never rendered into a prompt, so adding profile fields does not change prompt text or versions unless a template uses them. The one profile field that reaches a prompt is the Gmail scope (SOW-0031): `mailScopeQuery` in `src/server/domain/mail-filter.ts` turns it into a Gmail search that `agent-source.ts` renders on a line of its own in the `sync_mail` "Mailbox scope" section (v3; v4 from SOW-0032 adds `scope_message_count`, the count the scope query returns on its own without date limits, null without a scope; only an explicit 0 on a scoped run adds the "matched no mail" note to the summary). Probed 2026-11-09 with the v4 strict schema and a trivial no-tools prompt that named the values to return: `claude -p --json-schema` (2.1.319) returned the field as 0 and `codex exec --output-schema` (0.163.0) as null, both exit 0. This proves the schema is accepted, not how either agent counts on a real scoped sync; an agent that always answers null makes the warning silent, which is allowed. It is user text inside the prompt, so keep the one-line validation, and never put it in argv. Labels use Gmail's hyphen form (`Jobs/Frontend` → `label:Jobs-Frontend`), probed against the claude.ai Gmail connector on 2026-11-09; Codex and custom agents' Gmail tools were not probed.
- Handlers call `ctx.recordAgent(requestedAgent(adapter))` before `adapter.run` and `reportedAgent(result)` after it, before checking `ok`, so failed runs keep the record (`src/server/runs/agent-record.ts`).
- User cancel (SOW-0012) reuses the run's abort signal, so the adapter's kill path is unchanged. Handlers call `ctx.beginSaving()` right after a valid agent result and before any slow or writing step (discovery: before link checks; mail sync: before proposals); it throws `Aborted` if a cancel or shutdown came first, and afterwards cancel is refused with 409.
- The Run page's readable log (`src/ui/log-format.ts`, SOW-0013) depends on the Claude stream-json and Codex `--json` event shapes. When a preset's output format or a CLI version changes, update the formatter and `test/ui/log-format.test.ts` with it; unknown event types are hidden, so drift shows up as missing rows, not errors.
- The output schema handed to agents (`outputJsonSchema` in `src/server/tasks/schemas.ts`) must stay in the strict shape: no `$schema` pointer, no `default` keywords, `additionalProperties: false` on every object, every property in `required`. Claude Code's validator rejects zod's draft-2020-12 `$schema` pointer, and the OpenAI API behind Codex rejects anything non-strict with HTTP 400 `invalid_json_schema`. `test/server/tasks/schemas.test.ts` pins this. Evidence: SOW-0007.
- Claude Code's Gmail path depends on the claude.ai Gmail connector tools named in `DEFAULT_SETTINGS.allowed_tools_sync`. Smoke-run status (2026-11-06, claude 2.1.319, codex 0.163.0): both presets accept both task schemas and return structured output for a trivial prompt. A full discovery or sync run with real web search or Gmail has NOT been recorded yet; do not claim that without one. Evidence: SOW-0007 Validation.

- CV analysis (SOW-0023) is a third task kind, `analyse_cv` (`AgentTaskKind = RunKind | 'analyse_cv'`; the adapter factory, `renderPrompt` and `outputJsonSchema` take it). It runs from `src/server/cv/service.ts`, outside the run queue, with a fixed 5-minute timeout and its own abort controller per analysis; analyses of different owners (each profile, plus the new-profile one, SOW-0024) run side by side, so several CV agents may run at once; shutdown aborts them all and leaves the row `running` for the next start to mark `interrupted`, and after `stop()` the service refuses `start()` (also one still extracting text) and `retry()`, so no agent is spawned during shutdown. pdf.js documents from `unpdf` are released with `pdf.loadingTask.destroy()`; the proxy has no `destroy()` at runtime although its type declares one. `cvAdapterConfig()` in `presets.ts`: Claude gets the isolation settings, `--disallowedTools Agent,Task`, `--tools ""` and `--strict-mcp-config`, and no `--permission-mode`/`--allowedTools`; Codex gets `--sandbox read-only`, `-c web_search="disabled"` (its default is a cached search, not off; probed on 0.163.0 2026-11-07: valid draft in 11.9 s), `--disable multi_agent` and `-` as the prompt with `promptVia: 'stdin'` (a CV prompt in argv would hit Linux's 128 KiB per-argument limit or Windows' 32,767-character command line; `codex exec --help` 0.163.0: "If not provided as an argument (or if `-` is used), instructions are read from stdin"); both get selection `{ model: '', effort: '' }` (agent defaults). Custom commands run as configured. Discovery and sync argv are pinned unchanged by tests. Real probe 2026-11-07 with an invented CV: Claude Code 2.1.319 returned a valid draft in 7.3 s (about $0.05, 4,740 input tokens); codex-cli 0.163.0 in 13.5 s. The CV text reaches the agent only in the prompt (the app extracts it with `unpdf`/`mammoth`); the run folder `cv-analyses/<id>/work/` holding `prompt.md` is deleted when the agent ends. Agent output is bounded by `toProfileDraft()` (`src/server/cv/draft.ts`).

## Best Practices

- The fake agent never validates the schema it receives. Any change to `outputJsonSchema` or a preset flag needs a real `claude -p … --json-schema` and `codex exec --output-schema` probe with a trivial prompt (stdin redirected from `/dev/null`, otherwise codex waits for more input).
- Test adapter behaviour with `test/fixtures/fake-agent.mjs` modes (`ok`, `prose`, `claude`, `claude-fail`, `claude-budget`, `codex`, `fail`, `hang`, `hang-tree`, `echo-argv`, plus the `debug models` catalog probe) and `process.execPath`; never require a real agent in CI.
- When a run must be killed, the whole process group dies on POSIX (`detached: true` + `kill(-pid)`) and `taskkill /T /F` on Windows; prove it with a pid file written by the fixture.
- Validate agent output with the zod schema in the task layer, never in the adapter.

## Bad Practices

- Interpolating the prompt into argv for presets that take stdin or a file.
- Catching the UNIQUE/parse error instead of checking first.
- Changing a prompt without bumping `version:` and the test that pins it.
- Treating a `mail_access: false` run as "no news".

## Workflow Checklist

1. Read the preset and the fixture mode you will touch.
2. Write or update the fake-agent test first (RED), then change the adapter.
3. If a flag changes, run the CLI's `--help` and record the version in the commit body.
4. Run `npx vitest run test/server/agents` and the e2e `test/e2e/discovery-flow.test.ts`.

## Validation Checklist

Before claiming done:

- `npm test` pristine (no leaked processes: the hang tests assert the pid is dead).
- Prompt version bumped and `test/server/tasks/prompts.test.ts` updated when wording changed.
- The spec section 7 contract (output shapes) still matches `src/server/tasks/schemas.ts`.
- Same-failure scan: `grep -rn "shell: true\|exec(" src/server` returns nothing.
